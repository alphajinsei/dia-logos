育休おめでとうございます。私のおすすめは、todoリストの軸を**時間**にすることです。育休は始まりと終わりが決まっていて、その間に子どもが毎日育っていく期間です。この二つを画面に出すと、ただのリストではなく「この期間の記録」として読めるページになります。

## おすすめ：育休タイムライン型

```
育休 Day 45 / 180  ━━━━━━━━░░░░░░░░░░░░  残り135日

  ● 10/12  Terraformで自宅ラボ構築  ✅
  │        「思ったより夜泣きの合間にできた」
  ┊ 10/20  👶 はじめて笑った
  ● 10/28  Qiita記事を1本書く  ✅
  ┊
  ○ ----   拡散モデルを実装する（進行中）
  ○ ----   運転免許の住所変更
```

一工夫は次の3点です。

1. **残り日数のプログレスバー**：経過日数と完了数を並べます。バーンダウンチャートのように、時間の進み具合と自分の進み具合の差が見えます。
2. **子どもの節目を同じ時間軸に混ぜる**：「寝返りした週にこれを終わらせた」という並びになり、育休中ならではの記録になります。後から読み返して一番価値が出るのはここだと思います。
3. **完了時に一言を残す**：チェックを付けるだけでなく、感想や学びを1行書きます。これが溜まると、育休明けにそのまま振り返り記事の材料になります。

「できる自分を見せる」ページではなく「この期間の記録」になるので、見せびらかす感じも出にくいと思います。

## 別のアイデア

- **「やめたこと」も残す**：育休は予定通りに進まないのが普通です。諦めたtodoを理由付きで残すと、正直で読み物として面白いページになります。
- **物理のメタファーで見せる**：完了したtodoが星になって星座が育っていく、エネルギー準位図のように上がっていく、といった見た目にします。ポートフォリオと同じく、ちょっと遊べます。
- **更新はClaude Codeに任せる**：todoはYAMLかMarkdownで持ち、「◯◯終わった、感想は△△」と私に言えば、ファイルを更新してcommit・pushまで行います。そこから先は今使っているCloudflare Pagesの仕組みがそのまま公開してくれます。抱っこしながらでも更新できるので、続けやすさの面で一番効くと思います。

## 一点だけ注意

インターネットに公開するので、**子どもの名前・顔写真・生年月日がわかる情報は載せない**ほうが安全です。「Day 45」「生後◯週」のように相対的な書き方にしておけば、時間軸を混ぜる良さはそのまま残せます。

## 設計の軸：自己決定理論（SDT）の3要素

動機づけ研究の自己決定理論（Deci & Ryan）では、人が自発的に動き続けるには次の3つが必要だとされています。

| 要素 | 意味 | 育休中に欠けやすい理由 |
|---|---|---|
| 自律性 | 自分で決めた、という感覚 | 実は十分ある（時間の使い道は自由） |
| 有能感 | 進んでいる・できている、という感覚 | 成果が見えないと実感できない |
| 関係性 | 誰かに見られている・つながっている、という感覚 | 職場がなくなり、ほぼゼロになる |

育休で失われるのは、主に関係性と、締切や評価という外圧です。物理でいえば、駆動力のない系は平衡状態（YouTube）に落ちていきます。サイトの役割は、外から周期的に揺さぶりをかけることだと考えています。

## 入れたいプラスアルファ（優先順）

**1. 期限を公開し、延期の跡を消さない**
期限を守れなかったら、元の期限を取り消し線で残したまま延期します。例：`~~11/15~~ → 11/30（延期1回）`。罰は与えず、記録だけを残します。損失回避が効きますし、正直な記録にもなります。育児で崩れるのは前提なので、延期は恥ではなく、ただの履歴という扱いにします。

**2. 完了の条件を「公開物」にする**
「本を読む」ではなく「読書メモをはてなに書く」、「個人開発」ではなく「GitHubに公開して、Qiitaに記事を書く」を完了とします。各タスクに成果物へのリンクを付けます。終わったかどうかが外から確認できるので、自分を騙せなくなります。今お持ちの発信環境もそのまま活きます。

**3. Claudeを外部刺激として定期的に動かす**
これが一番効くと思います。Claude Codeのスケジュール実行（routine）を使って、たとえば次のことをさせます。

- 毎週月曜：リポジトリを読み、先週の進捗と今週期限のタスクを週報にまとめてサイトに載せる
- 期限の3日前：「◯◯の期限が近いです。次の一手は△△では？」と通知する

上司やチームメイトの代わりになる、外から突いてくる存在を人工的に用意するという発想です。

**4. タスクごとに「なぜやるか」と「次の一手」を書く**
- なぜやるか：自律性を守るためのものです。外発的な報酬（ポイントやバッジなど）ばかりにすると、内発的な動機がかえって弱まることが知られています（アンダーマイニング効果）。ゲーム化はやりすぎないほうがいいと思います。
- 次の一手：「Terraformの公式チュートリアル1章」のように、隙間の15分で手を付けられる粒度にします。YouTubeを開く代わりの選択肢になります。

**5. 育休の残り日数と、その日数で見込める完了ペースの線**
「残り120日、このペースだと完了は6/15件」と表示します。時間が有限だという感覚（GMOの社長の話の核心）を、毎回目に入る形にします。

## 行動原理の外部化と法典のたとえについて

法典のたとえはよく当てはまっていると思います。その場の気分（本能）で判断せず、事前に決めて書いておいたルールに判断を委ねる、という構造です。このtodoサイトは**自分用の法典**にあたります。そう考えると、設計の方針も一つにまとまります。

> **判断はタスクを登録するとき（頭がはっきりしている時）に済ませておき、実行するときは書いてある通りに動くだけにする。**

YouTubeを開きかけた隙間時間に「何をやろうか」と考えさせた時点で、本能が勝ちます。なので「次の一手」を事前に書いておくことが大事になります。

## SDTの表の訂正

ご指摘の通りで、前回の表は不正確でした。訂正します。

- **自律性**：むしろ過剰なくらいにあります。何をしてもいいので、何もしない自由もあるという状態です
- **有能感**：仕事という評価の場がなくなるので、やや減ります
- **関係性**：大きく失われます。ここが本丸です

さらに言うと、締切や上司のような**外部構造**はSDTの3要素には入っていません。いま本当に欠けているのは「関係性」と「外部構造」で、後者はSDTより、ご自身が言う「外部化」という言葉のほうが的確に表していると思います。

## Claudeによる定期実行の実装

ノートPCは不要です。Claude Codeには**クラウドで動くスケジュール実行（routine）**があり、`/schedule` で設定できます。PCが閉じていても、Anthropic側の環境でcronのように起動し、GitHubリポジトリを読んで作業します。公開サイトをインターネット越しに見に行く必要もなく、リポジトリの `tasks.yaml` を直接読めば済みます。

ただ、役割は二つに分けるのがいいと思います。

| 役割 | 担当 | 理由 |
|---|---|---|
| 期限前リマインド（機械的な処理） | GitHub Actionsのcron | 判断が要らないので安く確実 |
| 週次レビュー・助言（判断が要る処理） | Claudeのroutine | 「この停滞はタスクが大きすぎるのでは、分割しませんか」のような助言はLLMにしかできない |

通知先の候補は次の通りです。

- **GitHub Issueで自分にメンション** → メールとGitHubアプリのプッシュ通知が届きます。設定がほぼ要らず、まずはこれがおすすめです
- **Discordのwebhook** → スマホにプッシュ通知が届きます。Discordを使っているなら一番手軽です
- **LINE** → LINE Notifyは2025年3月に終了しているので、Messaging APIでbotを作る必要があります。可能ですが手間がかかります
- **メール** → Resendなどのメール送信APIを使います。こちらも可能です

routineから使えるコネクタなどの細かい仕様は、実装するときに確認します。

## 時間が有限であることの表現（育休スコープなし）

二つ提案します。

1. **人生を週単位のマス目で表示する**（Tim Urbanの "Your Life in Weeks"）：90年分の約4,700マスを並べ、過ぎた週は塗りつぶし、今週は光らせます。完了したタスクは、その週のマスに印として残します。ずっと使い続けられて、有限であることが一目でわかります。生年が必要ですが、公開ページでは年齢がわからない表示にもできます。
2. **放置日数**：各タスクに「最後に進捗があってから◯日」を表示します。期限よりも日常的に効きます。

## いただいたリストの整理

性質で分けると、4種類になります。

| 種類 | タスク | 完了の概念 |
|---|---|---|
| 📚 読書 | 半導体戦争 / テクノロジカル・リパブリック（再読）/ ゼロ・トゥ・ワン / ゼロから作るDeep Learning 6 | あり（短い） |
| 🛠 プロジェクト | ブログ自作 / 株の自動売買 / ゲーム / 役に立つサービス | あり（長いので分割が必要） |
| 🧭 調査・決定 | オントロジー・認証の勉強 / 次の資格を決める | あり（成果物は「結論と理由」） |
| 🔁 習慣 | 毎日のインプットとアウトプット | なし → 継続日数で見る |

いくつか補足です。

- **毎日のインプット**：毎日ブログを1本書くのはハードルが高すぎます。そこで、**サイト内に短い「着想メモ」欄**を作るのを提案します。日経などで読んだことと自分の考えを数行書くだけです。GitHubの草のようなヒートマップで継続が見え、良いメモが溜まったらブログ記事に昇格させます。
- **ブログ自作**：このtodoサイトに着想メモと読書メモが載るなら、これ自体がブログの原型になります。一石二鳥なので、最初のプロジェクトにしてもいいと思います。
- **役に立つサービス / ゲーム**：このままだと大きすぎて、次の一手が書けません。最初のタスクは「アイデアを10個出して1つに絞る」にして、成果物は選定理由の記事にするのが良いと思います。

## タスクのテンプレート

```yaml
- id: semiconductor-war
  title: 半導体戦争を読む
  type: book            # book / project / study / decision
  status: active        # inbox / active / done / dropped
  why: 半導体はAIと地政学と株の交点。物性屋として構造を理解したい
  output: はてなに読書メモ（要点3つ＋自分の考察）
  next_action: 第1部を読む（通勤時間相当の30分）
  deadline: 2026-11-20
  deadline_history: []  # 延期すると [2026-11-15] のように旧期限が積まれる
  created: 2026-11-01
  last_progress: 2026-11-01
  links: []             # 完了時に成果物のURL
```

「書けないから登録しない」を防ぐ仕組みとして、**`inbox` 状態を作ります**。思いついたらタイトルだけで登録し、`why`・`output`・`next_action`・`deadline` の4項目が埋まった時点で `active` に昇格させます。埋めるときは私に相談してください。成果物の案出しを一緒にやります。

ルールをもう一つ足すなら、**同時に `active` にできるのは3つまで**にするのがおすすめです。手を広げすぎて全部が止まるのを、ルールの側で防げます。
