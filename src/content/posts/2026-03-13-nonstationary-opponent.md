## なぜDQNで対戦ゲームが難しいか

通常のDQNは「環境が固定」を前提にしていますが、対戦ゲームは**相手も変化する**ので工夫が必要です。

主な手法：

- **Self-play** — 自分自身と対戦させて学習（AlphaGoもこれ）
- **Fixed opponent** — ランダムAIや一定強さの相手と対戦
- **Experience Replay** — 過去の自分と対戦

---

## 基本的な答え：「相手込みで環境とみなす」

あなたの直感は正しいです。**相手の動きを環境の一部として吸収する**のが最もシンプルな考え方です。

つまり、エージェントから見た世界観はこうなります：

```
自分が行動を選ぶ
  ↓
環境（＝盤面 ＋ 相手の応手）が次の状態と報酬を返す
  ↓
自分が次の行動を選ぶ…
```

FrozenLakeと構造は**全く同じ**です。ただし「環境のステップ処理」の中に相手の着手が含まれているというだけです。

---

## 「相手が賢くなると環境が変わる」問題

ここがご指摘の核心ですね。これは**非定常環境問題**と呼ばれます。

通常のDQNは環境が固定（定常）であることを前提にしています。ところが相手が強化学習で成長していくと、同じ状態・行動に対する報酬の分布が時間とともに変わってしまいます。

この問題への対処法がいくつかあり、**難易度順**に以下のようになります。

### ① 相手を固定する（最も簡単）

相手はランダムAI、もしくは強さが固定のルールベースAIにする。環境が定常になるので、通常のDQNがそのまま使えます。

欠点として「ランダム相手に強くなっても人間には弱い」ということが起きます。

### ② カリキュラム学習（中程度）

段階的に相手を強化していきます。

```
Phase 1: ランダム相手で学習
Phase 2: Phase1で学習したAIを相手に学習
Phase 3: Phase2で学習したAIを相手に学習…
```

相手の強さが徐々に上がるので、エージェントも着実に成長します。**今回の実装にはこれが最もおすすめ**です。

### ③ Self-play（本格的）

エージェントが常に「現在の自分自身」と対戦します。AlphaGoがこの方式です。

理論的には最も強くなりますが、**学習が不安定になりやすい**という問題があります。同じ学習率・探索率でも、相手が同時に変わり続けるため、うまく収束しないことがあります。Experience Replay（過去の自分）と組み合わせることで安定しやすくなります。

---

## もう一つの考え方：Two-agent視点

上記はすべて「片方だけ学習する」前提でした。もう一つのパラダイムとして、**両方のエージェントを同時に学習させる**方法（Multi-Agent Reinforcement Learning, MARL）があります。

ただしこれは理論的に複雑になるので、今回は「片方だけ学習、相手は固定 or 段階的強化」で十分です。

```

│     ├── エージェントの着手を盤面に反映
```

## 問題の診断

### 問題① εが早く下がりすぎている

500エピソード時点でε=0.05になっています。9×9の盤面は状態空間が膨大なので、探索が全然足りていません。

```
現在: epsilon_decay=0.9995 → 500ep付近でε≒0.05に到達
理想: 2000〜3000ep付近でε≒0.05に到達すべき
```

### 問題② 報酬が sparse すぎる

現在の報酬設計：
```
勝ち  → +1
負け  → -1
途中  →  0  ← ゲーム中ずっとこれ
```

1ゲームが数十手あるのに、報酬が最後の1手にしかつかないため、Q値の伝播が非常に遅いです。

### 問題③ ネットワークが9×9盤面に対して浅い

現在は盤面をflattenして全結合のみです。盤面の**空間的なパターン**（連続した石の並び）を学習するには、本来CNNが向いています。ただしNumPy手書きで実装できます。

### 問題④ バッファ容量が小さい・バッチサイズも小さい

```
現在: capacity=10000, batch_size=64
改善: capacity=50000, batch_size=128
```

## 今回の修正まとめ

**① εの減衰を遅くした（`0.9995 → 0.99985`）**

前回は500ep時点でε=0.05（探索ほぼゼロ）になっていました。9×9盤面で状態空間が膨大なのに、ランダム探索が早く終わりすぎていたのが主な原因でした。

**② 中間報酬を追加した**

```
自分が4連を作った     → +0.3
相手の4連を阻止した   → +0.2
```

勝敗だけが報酬だと、1ゲーム数十手の中で最後の1手にしか信号がなく、Q値の伝播がひどく遅くなります。中間報酬を入れることで、「この手は良い手だった」という信号が毎ステップ届くようになります。

**③ バッファ・バッチサイズを拡大（`10000→50000`, `64→128`）**

サンプルの多様性と学習の安定性が上がります。
